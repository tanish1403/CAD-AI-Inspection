# CAD-AI Inspector — Option A (Pretrained AI Only)

**Kaggle GPU · Grounding DINO Tiny + DINOv2 Small · Zero-shot / reference similarity**

This is the Option-A implementation selected for the assignment. It uses existing pretrained weights only:
- **Grounding DINO Tiny** (`IDEA-Research/grounding-dino-tiny`) — open-vocabulary text-prompted object proposals.
- **DINOv2 Small** (`facebook/dinov2-small`) — pretrained visual embeddings for comparing detected real-image crops with CAD-derived component reference crops.

No model is trained or fine-tuned. No labelled training dataset is required. The system uses the supplied JSON/mask as the expected-part inventory and the CAD render as a visual reference.

> **Scientific honesty:** We cannot execute the pretrained model downloads or GPU inference in this authoring environment because it has no outbound network access and does not have `transformers` installed. The project includes a Kaggle notebook that downloads the official pretrained weights and runs the full inference experiment on the supplied images. We have run actual dataset audits and code/data-loader checks here; the model inference results must be generated by running that notebook on Kaggle. Do not report model accuracy until you have labelled ground truth.

## 5. Outputs

Each run creates:
```text

├── annotated_result.png
├── inspection_results.csv
├── inspection_results.json
└── debug/

```
`PRESENT` means a text-detected candidate also passed the configured CAD-reference embedding similarity threshold. `UNCERTAIN` means there is not enough evidence. `ABSENT` is only returned if a real-image expected ROI is supplied and explicitly marked visible, but no candidate overlaps that ROI.

## 6. How the AI pipeline works

1. Parse component names and stencil IDs from the JSON.
2. Extract each part's reference crop from the CAD render using its mask ID.
3. Group components into broad text-query families (bolt, washer, nut, cover, box).
4. Run Grounding DINO once per family to obtain real-image candidate boxes.
5. Extract DINOv2 embeddings for CAD reference crops and detected real-image candidates.
6. Rank candidates by cosine similarity and detector confidence.
7. Produce per-part `PRESENT` / `UNCERTAIN` / conditionally `ABSENT` results and annotated overlays.

Grounding DINO is an open-set detector prompted by text. DINOv2 is a feature extractor, not a classifier trained to recognize the supplied part taxonomy. Their scores are ranking signals, not calibrated probabilities.

## 7. Important limitation: missing-part logic

**A detector failing to find a bolt is not proof that the bolt is absent.** It may be small, occluded, poorly lit, outside the detector's vocabulary, or missed due to image scale.

To make an `ABSENT` decision, provide a real-image ROI obtained from a human annotation or a validated CAD-to-camera registration:
```json
{
  "parts": {
    "Bolts_M8_1": {
      "bbox": [120, 80, 220, 190],
      "visible": true
    }
  }
}
```
Coordinates are `[x_min, y_min, x_max, y_max]` in the real image. Set `visible: true` only when the location is confirmed to be visible and not occluded. Then:
```bash
python scripts/run_inspection.py --case data/input/my_case \
  --output outputs/my_case --rois configs/my_real_rois.json
```
The example ROI file is a format template only; its dummy coordinates are not actual annotations.

## 9. Experiment methodology and metrics

The notebook saves predictions for every supplied real view. Since the assignment archive does not provide per-part ground-truth present/absent labels for every view, report detection counts and uncertainty coverage, not precision/recall/accuracy.

For quantitative evaluation, manually annotate a holdout set with `PRESENT`, `ABSENT`, and `OCCLUDED/UNCERTAIN` labels. Then compute:
- Precision, recall and F1 for present components.
- Missing-part recall and false-absence rate.
- Uncertain/review coverage.
- Detection localization IoU if bounding boxes are annotated.

Do not tune thresholds on the same images used for final evaluation.

## 10. Configuration

Edit `configs/config.yaml`:
- `max_image_side`: inference resize limit; increase for tiny parts if GPU memory allows.
- `grounding_box_threshold` and `grounding_text_threshold`: proposal thresholds.
- `present_threshold`: minimum combined ranking score to call a match.
- `part_aliases` / family prompts: adapt prompts if the component vocabulary is weak.

Thresholds in this project are initial values and must be calibrated on real examples. The combined ranking score is not a probability.

## 11. Troubleshooting

- **CUDA OOM:** lower `max_image_side` to 960 or 768; run on CPU only as a fallback.
- **No boxes:** inspect family prompts, lower thresholds carefully, or check that the model loaded correctly.
- **Wrong component matches:** improve component-specific aliases and use CAD reference crops; similar fasteners may remain ambiguous.
- **No CAD reference crop:** inspect the JSON stencil value and mask pixel inventory.
- **Hugging Face download failure:** check Kaggle internet setting, HF Secret, disk space, and rerun downloader.
- **Kaggle internet disabled:** enable internet in notebook settings or pre-download model snapshots and upload them to the runtime.

## 12. Problem Statement 2 extension
